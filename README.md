# 성격유형 검사 사이트 (v3.0)

이름을 입력하고 80문항에 답하면 성격유형을 계산해 보여 주고, 그 결과를 이름과 함께
저장합니다. 저장된 기록은 관리자 이메일로 받은 인증번호로 로그인해야 볼 수 있습니다.

- 화면: GitHub Pages (정적 파일, 빌드 도구 없음)
- 저장·인증: Supabase (무료 요금제로 충분)

## 무엇이 들어 있나

- 검사 세 단계 — 단순형 40문항, 일반형 80문항, 심화형 120문항(+ 혈액형·별자리)
- 문항 풀 400개에서 매번 무작위 출제
- 결과: 유형과 지표별 기울기, 강점과 눈여겨볼 점, 궁합, 어울리는 일 1~3순위
- 15개 유형 전부에 대한 연애·일·친구 궁합표
- 심화형에서 혈액형·별자리를 함께 넣으면 세 가지를 합친 서술과 조합 궁합 순위
- 시작 화면에 오늘 결과를 받은 인원수 표시
- 오늘의 운세 (날짜와 유형으로 문구를 고름, 화면 전용)
- 결과 PDF 내려받기
- 관리자 화면: 기록 조회, 이름 검색, CSV 내려받기, 삭제, 조합 미리보기

## 폴더 구성

```
index.html            검사 화면
admin.html            관리자 화면
assets/
  config.js           Supabase 접속 정보 (직접 채워야 함)
  questions.js        선택 방식 160문항, 척도 방식 240문항, 유형 설명·궁합·직업
  scoring.js          문항 뽑기, 채점, 유형 간 궁합 점수 계산
  app.js              검사 진행, 결과 표시, PDF 저장
  combo.js            혈액형·별자리·유형을 합친 서술과 조합 궁합
  admin.js            인증번호 로그인, 기록 조회
  fortune.js          오늘의 운세 문구
  styles.css
supabase/schema.sql   테이블과 접근 권한 설정
```

## 설치 순서

### 1. Supabase 프로젝트 만들기

1. supabase.com 에 가입하고 새 프로젝트를 만듭니다. 지역은 Northeast Asia (Seoul)를 고릅니다.
2. 왼쪽 메뉴 **SQL Editor** 에서 `supabase/schema.sql` 내용을 붙여 넣고 실행합니다.
3. 이어서 관리자 주소를 등록합니다. 파일 맨 아래 안내에 있는 한 줄을 따로 붙여 넣고
   주소만 자기 것으로 바꿔 실행하세요.

   ```sql
   insert into public.admins (email) values ('여기에-관리자-주소')
     on conflict (email) do nothing;
   ```

   **이 줄은 저장소에 올리지 마세요.** 관리자 주소는 데이터베이스 안에만 두고,
   저장소 어디에도 남기지 않는 구조입니다.

### 2. 관리자 계정 등록

**Authentication > Users > Add user** 에서 1단계에 등록한 것과 **같은 주소**를 넣습니다. 비밀번호는 아무 값이나
넣어도 됩니다. 이 사이트는 비밀번호를 쓰지 않고 인증번호로만 로그인합니다. 미리 등록된
주소가 아니면 인증번호 발송 자체가 거부되므로, 다른 사람이 관리자 화면에 접근할 수 없습니다.

### 3. 메일 발송 서버(Gmail) 연결

Supabase 기본 발송 서버를 쓰는 동안에는 **메일 서식을 고칠 수 없습니다.**
서식 화면에 "Set up custom SMTP to edit templates" 라는 안내만 뜹니다.
따라서 발송 서버부터 연결해야 합니다.

**3-1. Google 계정에서 앱 비밀번호 만들기**

Gmail 은 평소 쓰는 비밀번호로는 외부 프로그램의 발송을 허용하지 않습니다.

1. `myaccount.google.com/security` 에서 **2단계 인증**을 켭니다. 이게 켜져 있지 않으면
   다음 단계의 메뉴 자체가 나타나지 않습니다.
2. `myaccount.google.com/apppasswords` 로 갑니다.
3. 앱 이름에 `supabase` 처럼 알아볼 수 있는 이름을 넣고 **만들기** 를 누릅니다.
4. 화면에 나온 **16자리**를 복사해 둡니다. 창을 닫으면 다시 볼 수 없습니다.
   붙여 넣을 때 사이의 공백은 지웁니다.

> 앱 비밀번호 메뉴가 보이지 않으면 세 가지 중 하나입니다. 2단계 인증이 꺼져 있거나,
> 2단계 인증을 보안 키로만 설정했거나, 회사·학교 계정이라 관리자가 막아둔 경우입니다.
> 기관 계정이 막혀 있으면 개인 Gmail 주소로 만들어도 됩니다.

**3-2. Supabase 에 입력하기**

`https://supabase.com/dashboard/project/_/auth/smtp` 로 가거나,
**Authentication** → **Emails** → **SMTP Settings** 탭을 엽니다.
**Enable Custom SMTP** 를 켜고 아래대로 채웁니다.

| 칸 | 넣을 값 |
| --- | --- |
| Sender email | 앱 비밀번호를 만든 Gmail 주소 그대로 |
| Sender name | 성격유형 검사 (받는 사람에게 보이는 이름) |
| Host | `smtp.gmail.com` |
| Port | `465` (연결이 안 되면 `587`) |
| Username | Sender email 과 **똑같은** 주소 |
| Password | 3-1 에서 만든 16자리 |

**Sender email 과 Username 이 다르면 발송이 거부됩니다.** 구글은 로그인한 계정과
발신자가 같아야 메일을 내보냅니다.

> 커스텀 SMTP 를 켜면 발송 한도가 시간당 30건으로 잡힙니다. 관리자 한 명이 쓰기엔
> 넉넉하며, 값은 **Authentication > Rate Limits** 에서 볼 수 있습니다.
> Gmail 에서 보낸 메일이 기관 메일함에서 스팸으로 걸릴 수 있으니, 안 오면 스팸함을
> 먼저 확인하세요.

### 4. 인증번호(숫자) 방식으로 바꾸기

Supabase 는 기본값이 '클릭하는 링크'입니다. 메일 서식을 고쳐야 숫자가 발송됩니다.
링크와 숫자는 같은 기능을 쓰며, **어느 쪽이 발송되는지는 오직 서식 내용으로 결정**됩니다.

- 서식에 `{{ .ConfirmationURL }}` 이 있으면 → 링크가 발송됩니다.
- 서식에 `{{ .Token }}` 이 있으면 → 숫자 인증번호가 발송됩니다.
  자릿수는 프로젝트마다 다를 수 있습니다. 실제로 오는 자릿수를
  `assets/config.js` 의 `OTP_LENGTH` 에 맞춰 두세요. 기본값은 8 입니다.

**4-1. 서식 화면 열기**

`https://supabase.com/dashboard/project/_/auth/templates` 로 바로 들어가거나,
왼쪽 메뉴 **Authentication** → **Emails** → **Templates** 탭을 엽니다.
3단계를 마쳤으면 잠금 안내가 사라지고 입력칸이 열립니다.
서식 목록 중 **Magic link or OTP** 를 고릅니다.
`Confirm signup`, `Invite user`, `Reset password` 는 다른 용도이므로 건드리지 않습니다.

**4-2. 제목과 본문 바꾸기**

Subject heading(제목):

```
[성격유형 검사] 관리자 인증번호 {{ .Token }}
```

Message body(본문) 안의 내용을 모두 지우고 아래를 붙여 넣습니다.
기존 `<a href="{{ .ConfirmationURL }}">...</a>` 줄이 **한 글자도 남지 않아야** 합니다.

```html
<h2>관리자 인증번호</h2>
<p>아래 여덟 자리 번호를 1분 안에 입력하세요.</p>
<p style="font-size:28px;letter-spacing:6px"><b>{{ .Token }}</b></p>
<p>본인이 요청하지 않았다면 이 메일을 무시하세요.</p>
```

**Save changes** 를 누릅니다.

**4-3. 유효 시간 줄이기**

`https://supabase.com/dashboard/project/_/auth/providers` 에서 **Email** 을 펼치고
**Email OTP Expiration** 값을 `60` 으로 바꾼 뒤 저장합니다. 기본값은 3600(1시간)입니다.
화면이 60을 받지 않으면 허용되는 가장 작은 값으로 두세요. 이 값이 실제 유효 시간이고,
사이트에 보이는 1분 카운트다운은 안내용입니다.

### 5. 접속 정보 넣기

**Project Settings > API** 에서 Project URL 과 anon public key 를 복사해
`assets/config.js` 에 넣습니다.

```js
export const SUPABASE_URL = "https://xxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";
export const OTP_WINDOW_SECONDS = 60;   // 인증번호 입력 제한 시간(초)
export const OTP_LENGTH = 8;            // 메일로 오는 인증번호 자릿수
```

관리자 주소는 코드에 두지 않습니다. 관리자 화면에서 직접 입력하며, 누가 기록을 볼 수
있는지는 데이터베이스의 `admins` 표가 정합니다. 저장소를 통째로 공개해도 관리자 주소는
드러나지 않습니다.

anon key 는 공개되어도 되는 값입니다. 실제 차단은 데이터베이스 권한 설정이
담당합니다. **service_role key 는 절대 넣지 마세요.**

### 6. GitHub 에 올리고 공개하기

`index.html` 이 저장소 맨 위에 오도록 올립니다. 폴더째 올리면 주소가 404 가 됩니다.

```bash
git init
git add .
git commit -m "성격유형 검사 사이트"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

저장소 **Settings > Pages** 에서 Source 를 `Deploy from a branch`,
Branch 를 `main` / `/ (root)` 로 두고 저장하면 몇 분 뒤 주소가 나옵니다.
그 화면의 "Your GitHub Pages site is currently being built from the main branch" 는
어느 브랜치에서 배포하는지 알려주는 고정 문구입니다. 완료 여부는 페이지 맨 위 초록 상자나
저장소 **Actions** 탭의 `pages-build-deployment` 항목으로 확인합니다.

마지막으로 Supabase **Authentication > URL Configuration > Site URL** 에
그 주소를 넣어 둡니다.

### 7. 공개 전 확인

로그인 없이 남의 기록을 읽을 수 없어야 합니다. 명령창에서 실행해 확인하세요.

```bash
curl "https://<프로젝트주소>.supabase.co/rest/v1/mbti_results?select=*" \
  -H "apikey: <anon키>" -H "Authorization: Bearer <anon키>"
```

`[]` 가 나오면 정상입니다. 기록이 줄줄이 나오면 `schema.sql` 이 제대로 실행되지 않은
것이니 SQL 을 다시 돌리고 재확인하세요.

## 문항과 채점

검사는 세 단계이고, 시작 화면에서 하나를 고릅니다. 문항이 많을수록 지표의 기울기가
촘촘하게 잡힙니다.

| | 문항 수 | 방식 | 걸리는 시간 | 혈액형·별자리 |
| --- | --- | --- | --- | --- |
| 단순형 | 40 | 척도(일곱 단계) | 약 5분 | 없음 |
| 일반형 | 80 | 선택(네 답 중 하나) | 약 12분 | 없음 |
| 심화형 | 120 | 두 방식 절반씩 | 약 18분 | 있음 |

**선택 방식** — 상황을 묻고 네 개의 답 중 하나를 고릅니다. 일반형이 이 방식이고,
심화형의 절반이 여기서 나옵니다.

- 문항 풀은 지표당 40문항, 모두 160문항입니다.
- 선택지는 한쪽 극에서 반대쪽 극으로 기울기가 옮겨가며, 각각 그 자체로 완결된 문장이라
  다른 선택지와 견줘 볼 필요가 없습니다.
- 방향이 뚜렷한 선택지는 2점, 약한 선택지는 1점입니다.
- 뽑힌 문항의 절반은 선택지 순서를 뒤집어 보여 줍니다. 맨 위 선택지만 계속 고르는 습관이
  특정 유형으로 쏠리지 않게 하려는 장치이며, 채점 값은 순서와 무관하게 유지됩니다.

**척도 방식** — 문장 하나를 읽고 얼마나 그런지 일곱 단계로 표시합니다. 단순형이 이 방식이고,
심화형의 나머지 절반이 여기서 나옵니다.

- 문항 풀은 지표당 60문항, 모두 240문항입니다.
- 매우 그렇다 3점, 그렇다 2점, 조금 그렇다 1점, 가운데 0점이며 그렇지 않다 쪽도 같습니다.
- 지표마다 '그렇다가 앞 극'인 문장과 '그렇다가 뒤 극'인 문장을 절반씩 뽑습니다.
  계속 그렇다만 누르거나 그렇지 않다만 눌러도 특정 유형으로 쏠리지 않습니다.

**심화형** — 지표마다 선택 방식 15문항, 척도 방식 15문항씩 뽑아 모두 120문항입니다.

- 두 방식의 만점이 달라서(선택 방식 지표당 30점, 척도 방식 45점) 척도 쪽을 2/3 로 맞춰
  양쪽이 같은 무게로 반영되게 합니다.
- **혈액형과 별자리는 심화형에서만 입력합니다.** 단순형·일반형에는 나오지 않고 저장도 되지 않습니다.

**공통**

- 두 방식의 문항 풀을 합치면 400문항입니다. 출제 순서도 매번 섞입니다.
- 어느 단계든 지표마다 같은 수를 무작위로 뽑습니다. 어느 지표도 더 많거나 적게 나오지 않습니다.
- 중립 선택지는 선택 방식에는 두지 않았습니다. 방향이 흐려지는 것을 막기 위해서입니다.
- 두 극이 같은 점수면 방향이 뚜렷한 응답이 많은 쪽으로 정하고, 화면에 동률임을 표시합니다.
- 한 쪽(5문항)을 다 채우면 다음 쪽으로 자동으로 넘어갑니다. 다만 '이전'을 눌러 되돌아온
  쪽에서는 자동으로 넘어가지 않고 '다음'을 직접 눌러야 합니다. 마지막 쪽도 자동으로
  넘어가지 않습니다.

## 혈액형 · 별자리

심화형을 골랐을 때만 입력칸이 나타나며, 둘 다 선택 항목입니다. 넣지 않으면 결과에서
해당 절이 나오지 않습니다.

- 혈액형: A · B · O · AB 중 하나, 또는 모름
- 별자리: 목록에서 직접 고르거나, 생일을 `09-03` 처럼 넣으면 자동으로 정해집니다

결과에서는 세 가지를 합쳐 보여 줍니다.

**「A형 · 양자리 · ISTJ 인 사람」** — 세 가지가 같은 방향을 가리키는 지점은 '더 짙어지는 면'
으로, 서로 다른 지점은 '두 갈래로 보이는 면'으로 묶어 한 사람의 서술로 만듭니다.

**조합으로 본 궁합 순위** — 상대가 될 수 있는 768개 조합(16유형 × 4혈액형 × 12별자리)을
모두 계산해 잘 맞는 다섯과 어려운 셋을 보여 줍니다. 성격유형 6, 혈액형 2, 별자리 2의
비중으로 합하며, 같은 유형이 목록을 채우지 않도록 유형마다 가장 높은 조합 하나씩만 뽑습니다.

**항목별로 따로 보면** — 혈액형끼리, 별자리끼리의 순위를 따로 보여 줍니다.
별자리는 불·흙·공기·물 네 원소로 나눠 계산합니다.

계산에 쓰는 값은 `combo.js` 의 `BLOOD_FIT`(혈액형), `ELEM_FIT`(별자리 원소),
`comboScore`(비중)에 있고, 각 항목이 가리키는 지표 방향은 `questions.js` 의
`BLOOD`·`ZODIAC` 안 `lean` 에 있습니다.

혈액형과 별자리로 성격을 나누는 것은 널리 알려진 이야기일 뿐 연구로 확인된 바가 없습니다.
결과지에도 그 문구를 넣어 두었으니 지우지 않으시길 권합니다.

## 궁합 점수 계산 방식

결과지의 궁합은 두 가지로 나눠 보여 줍니다.

**결이 잘 맞는 / 부딪히기 쉬운 유형** — 네 지표의 관계로 짝을 정합니다.

| 이름 | 조건 |
| --- | --- |
| 보완 | 네 지표 중 셋이 반대 |
| 동류 | 보는 방식(S/N)과 판단 방식(T/F)이 같음 |
| 정반대 | 네 지표가 모두 반대 |
| 어긋남 | 안팎 성향은 같은데 보고 판단하는 방식이 반대 |

각 유형이 잘 맞는 쪽 2개, 부딪히는 쪽 2개를 가지며, 어느 쪽에서 보아도 결과가 같습니다.
ENTP 화면의 INTJ 90% 는 INTJ 화면의 ENTP 90% 와 일치합니다.

**연애 · 일 · 친구 점수** — 15개 유형 전부를 상황별로 계산합니다. 무엇을 얼마나
반영하는지는 `assets/scoring.js` 의 `W` 에 그대로 적혀 있습니다.

| | 크게 반영 | 중간 | 적게 |
| --- | --- | --- | --- |
| 연애 | 보는 방식(S/N)이 같음 | 안팎 성향(E/I)이 서로 반대 | 판단 기준, 생활 방식이 반대 |
| 일 | 생활 방식(J/P)이 같음 | 판단 기준, 보는 방식이 같음 | 안팎 성향이 반대 |
| 친구 | 보는 방식이 같음 | 안팎 성향, 판단 기준이 같음 | 생활 방식이 같음 |

두 계산은 보는 각도가 달라서 순위가 어긋날 수 있습니다. 앞의 것은 성향의 결을,
뒤의 것은 상황별 맞물림을 봅니다.

어느 쪽도 통계 조사에서 나온 값이 아닙니다. 사람 사이의 실제 관계 만족도를 측정한 수치가
아니므로, 관계를 판단하는 근거로 쓰지 않도록 결과지에 안내를 넣어 두었습니다.

## 오늘 인원수

시작 화면 맨 아래에 "오늘 N명이 결과를 확인했습니다" 가 작게 나옵니다.

기록을 열어 세는 것이 아니라, `schema.sql` 의 `today_count()` 함수가 숫자만 돌려줍니다.
누구나 실행할 수 있지만 이름이나 결과는 나오지 않습니다. 하루 기준은 한국 시각입니다.
숫자를 받아오지 못해도 검사에는 지장이 없고, 그 줄만 비어 보입니다.

## 관리자 화면

로그인하면 두 가지 화면을 오갈 수 있습니다.

**검사 기록** — 저장된 결과 목록, 이름 검색, CSV 내려받기, 삭제.
표의 행을 누르면 그 사람의 혈액형·별자리·유형 조합으로 결과 화면이 바로 열립니다.

**조합 미리보기** — 성격유형·혈액형·별자리를 직접 골라 결과를 봅니다. 고르는 즉시
다시 그려지며, 이 화면에서 본 것은 기록에 저장되지 않습니다.

## 오늘의 운세

`assets/fortune.js` 에 직접 쓴 문구가 들어 있습니다. 문구 40개, 키워드 20개, 시간대 6개,
색 8개, 일의 종류 12개입니다.

날짜와 유형을 섞어 만든 값으로 문구를 고르기 때문에 서버가 필요 없습니다. 같은 날 같은
유형이면 몇 번을 새로고침해도 결과가 같고, 날이 바뀌면 달라집니다.
'오늘 기대 볼 것'과 '오늘 조심할 것'은 유형별 강점·주의 항목에서 그날치를 골라 씁니다.

운세는 화면에만 나오고 PDF 에는 들어가지 않습니다. 날짜가 박힌 내용이라 나중에 다시 보면
맞지 않기 때문입니다.

## 결과 PDF

결과 화면의 **PDF로 저장** 을 누르면 A4 파일이 내려받아집니다. 인쇄 창을 거치지 않습니다.

결과지를 통째로 찍지 않고 머리말·지표·강점·궁합·어울리는 일·꼬리말 덩어리별로 따로 찍은 뒤,
다음 덩어리가 남은 자리에 들어가지 않으면 통째로 다음 쪽으로 넘깁니다. 그래서 표나 카드가
쪽 경계에서 잘리지 않습니다. 내용이 길면 두 쪽으로 나옵니다.

화면을 그림으로 떠서 넣는 방식이라 PDF 안의 글자는 복사·검색이 되지 않습니다.

## 막힐 때

**서식 화면에 "Set up custom SMTP to edit templates" 만 보이고 편집이 안 된다**
발송 서버를 아직 연결하지 않았습니다. 3단계를 먼저 끝내야 4단계가 열립니다.

**`535 5.7.8 Username and Password not accepted`**
평소 쓰는 Gmail 비밀번호를 넣었거나, 앱 비밀번호 사이의 공백을 함께 붙여 넣었습니다.
16자리를 공백 없이 다시 넣으세요.

**`534` 또는 로그인 거부**
해당 Google 계정에 2단계 인증이 꺼져 있습니다.

**발신자가 내가 넣은 주소가 아니다 / 발송이 거부된다**
Sender email 과 Username 이 서로 다릅니다. 둘을 같은 주소로 맞추세요.

**메일에 숫자 대신 링크가 왔다**
서식에 `{{ .ConfirmationURL }}` 이 남아 있습니다. 또는 `Magic link or OTP` 가 아닌
다른 서식을 고쳤습니다. 4-2 를 다시 확인하세요.

**`Signups not allowed for otp` 오류**
해당 주소가 Authentication > Users 에 없습니다. 이 사이트는 새 계정을 만들지 않도록
막아 두었기 때문에, 관리자 주소를 먼저 등록해야 합니다. (2단계)

**인증번호 자릿수가 화면과 다르다**
`assets/config.js` 의 `OTP_LENGTH` 를 실제로 오는 자릿수로 바꾸세요. 이 한 곳만 고치면
안내 문구와 입력칸이 함께 맞춰집니다.

**`Token has expired or is invalid` 오류**
유효 시간이 지났거나, 이미 한 번 쓴 번호이거나, 최근에 새 번호를 받아 이전 번호가
무효가 된 경우입니다. 가장 마지막에 온 메일의 번호를 쓰세요.

**`Email rate limit exceeded` 또는 429 오류**
같은 주소로는 60초에 한 번만 요청됩니다. 1분 기다렸다가 다시 누르세요.

**`Error sending magic link email`**
Supabase 가 메일 발송에 실패했습니다. 3단계 SMTP 설정을 확인하세요. 기본 발송 서버는
Supabase 계정에 등록된 팀 구성원 주소로만 보낼 수 있어, 외부 주소로는 이 오류가 납니다.
자세한 실패 사유는 Authentication > Logs 에서 확인합니다.

**결과 저장에서 `Could not find the table` 오류**
`schema.sql` 을 실행하지 않았거나, 다른 프로젝트에서 실행했습니다. `config.js` 의 주소와
같은 프로젝트인지 확인하세요. 테이블이 분명히 있는데도 같은 오류가 나면 SQL Editor 에서
`NOTIFY pgrst, 'reload schema';` 를 실행합니다.

**결과 저장에서 `new row violates row-level security policy` 오류**
`schema.sql` 의 '결과 제출 허용' 정책이 적용되지 않았습니다. SQL 을 다시 실행하세요.

**관리자 화면에 기록이 하나도 안 보인다**
로그인한 주소가 `admins` 표에 없으면 읽기가 막힙니다. SQL Editor 에서
`select email from public.admins;` 로 등록된 주소를 확인하고, 로그인에 쓴 주소와
철자가 같은지 대조하세요.

**PDF 저장이 안 된다**
일부 앱 안의 화면(웹뷰)은 파일 내려받기 자체를 막습니다. 오른쪽 위 메뉴에서
'다른 브라우저로 열기'를 고른 뒤 다시 시도하세요.

**파일을 고쳤는데 화면이 그대로다**
브라우저가 예전 파일을 물고 있습니다. 시크릿 창에서 확인하거나 캐시를 지우세요.

**내 컴퓨터에서 파일을 열었더니 아무것도 안 뜬다**
`index.html` 을 더블클릭해 여는 방식은 브라우저 보안 때문에 동작하지 않습니다.
폴더에서 `python -m http.server 8000` 을 실행하고 `http://localhost:8000` 으로 접속하거나,
GitHub Pages 에 올린 주소로 확인하세요.

## 알아두실 점

- 결과는 참고 자료입니다. 같은 사람이 몇 주 뒤 다시 하면 한 지표가 바뀌는 일이 흔합니다.
  채용·인사·평가의 근거로 쓰지 않는 것이 좋습니다.
- 이름을 받는 순간 개인정보 수집에 해당합니다. 대상이 넓어지거나 기관 이름으로 안내가
  나가는 상황이라면 시작 화면에 수집 안내를 한 줄 두고, 보관 기간과 파기 시점을 정해
  두시기 바랍니다.
- 저장소에는 개인정보를 두지 않습니다. 관리자 주소는 데이터베이스의 `admins` 표에만 있고,
  화면 코드와 SQL 파일 어디에도 적히지 않습니다.
- 저장된 기록은 관리자만 읽을 수 있지만, 결과를 넣는 것은 누구나 할 수 있습니다.
  주소가 알려지면 장난 기록이 쌓일 수 있으므로, 관리자 화면에서 지울 수 있게 해 두었습니다.
- 궁합, 어울리는 일, 혈액형·별자리 대조는 통계로 검증된 것이 아닙니다. 관계나 진로를 정하는 근거로 쓰지 않도록
  결과지에 안내를 넣어 두었으니, 그 문구는 지우지 않으시길 권합니다.
